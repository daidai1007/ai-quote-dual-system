# 固定底座 R11 增加适用产品

本次只增加数据库规则关联，不修改 R11 计算公式，不修改底座目录售价、历史报价或人工已确认的附件快照；不需要重新部署 API、重新构建客户端或修改表结构。

## 线上执行

1. 在 Neon SQL Editor 选择当前程序实际使用的数据库及分支，先运行 `00-readonly-check.sql`，确认只有一条活动目录的 R11，且分类、名称为“底座 / 固定底座”。保存结果，便于前后核对。
2. 完整运行 `01-extend-r11-products.sql`，不要只选中部分语句。脚本使用事务、目录切换同款锁、规则身份检查及幂等插入；报错会回滚。本步骤只应作用于实际服务使用的数据库。
3. 再运行 `00-readonly-check.sql`。在原有 JS、JP、JM 关联之外，应增加以下六个编码，且 formulas 与执行前完全一致：

   | 产品 | 新增编码 |
   | --- | --- |
   | JQ | `JQ_EXP` |
   | JE（含单门、双门） | `JE`、`JE_SINGLE`、`JE_DOUBLE` |
   | JS 超宽柜 | `JS_WIDE_EXP` |
   | JP 超宽柜 | `JP_WIDE_EXP` |

   原有 JS、JP、JM 关联全部保留；没有给 JA、JK 等其他产品开放 R11。普通 JS/JP 原本已经支持。

## 客户端验收

1. 退出并重开客户端，确保重新获取附件目录。选中 JQ、JE 单门/双门、JS 超宽、JP 超宽分别新建报价，设置底座高度并选“固定底座”。
2. 确认附件弹窗中的固定底座成本不再为零；同一宽度、深度、底座高度、材质、材料单价、喷塑单价和附件数量下，新产品与原 JS/JP/JM 的底座成本应相同。
3. 用非目录尺寸、两个不同子柜的并柜、底座数量 2 分别验证：均按自身宽度、深度、底座高度套用 R11，不使用柜体总高度代替底座高度。
4. 再导出报价，核对成本明细与当前已确认的附件弹窗一致。

注意：已保存的历史报价/已确认弹窗快照不会被数据库迁移自动重写。旧报价需重新计算该固定底座并确认，才能生成新成本快照；只重新导出旧快照不会补算。

R11 原公式（单位 mm、kg、㎡、元）：

- 重量 = `(宽度-3+深度-53.3) × (底座高度+93.4) × 2.5 × 材质密度 × 0.000001 × 2`
- 材料成本 = `重量 × 材质单价`
- 喷塑面积 = `(宽度-3+深度-53.3) × (底座高度+93.4) × 0.000001 × 2`
- 喷塑成本 = `喷塑面积 × 喷塑单价`（不喷塑时沿用现有零喷塑规则）
- 辅材成本 = `0`
- 人工成本 = `36.8997 + 407.9576 × 宽度 × 底座高度 × 深度 × 0.000000001`
- 单位成本 = `材料成本 + 喷塑成本 + 辅材成本 + 人工成本`
- 附件行成本 = `单位成本 × 附件数量`，沿用程序既有金额舍入规则。

本迁移针对执行时的活动目录。以后若重新导入/切换附件目录，应核对新目录的 R11 关联，并在缺少上述产品时再次执行本脚本；历史 generated 导入包不代表最新线上补充规则。
