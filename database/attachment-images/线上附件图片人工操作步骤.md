# 线上附件图片人工操作步骤

## 目标和边界

本次把 `线上附件名称与图片汇总.docx` 中的 50 个附件名称和 28 张图片写入两张独立展示表：

- `calc.attachment_image_catalog`：名称、Word 行号、匹配方式和来源校验值；
- `calc.attachment_image_asset`：图片顺序、MIME 类型、SHA-256 和二进制图片。

24 个缺图附件只写入目录表，不写图片行，因此客户端图片单元格为空。`风机`和`过滤网`按名称前缀匹配其不同型号；其余附件按规范化后的完整名称匹配。该方案不更新 `attachment_price`、`attachment_selection`、报价结果表或任何公式、快速报价和 V3 辅材规则。

## 文件

按以下顺序使用：

1. `database/attachment-images/web/00-readonly-preflight.sql`
2. `database/attachment-images/web/01-create.sql`
3. `database/attachment-images/web/02-import.sql`
4. `database/attachment-images/web/03-readonly-verify.sql`

审计清单：`database/attachment-images/generated/attachment-image-manifest.json`

Word 来源 SHA-256 必须为：

`2eeaf27a213cc98b32c5629f5d94bb036479b05bf86b3030b4052c69925cf861`

## 人工执行

1. 在 Neon 控制台确认当前项目、分支、数据库和角色都是计划更新的线上目标。创建一个可恢复分支或确认时间点恢复可用。
2. 新建 SQL Editor，使用 UTF-8 完整运行 `00-readonly-preflight.sql`。确认 `calc.attachment_price` 存在，附件活动目录正常，并保存结果。若目标库、活动版本或权限不符合预期，停止。
3. 完整运行 `01-create.sql`。它只创建两张附件图片表。若事务报错，单独运行 `ROLLBACK;`，不要继续导入。
4. 完整运行 `02-import.sql`。不要选中部分语句运行，也不要手工修改其中的 Base64 图片内容。该事务会按 Word 名称更新 50 个目录行，先清除这些名称的旧图片，再写入 28 张新图片；计数不符时自动回滚。
5. 完整运行 `03-readonly-verify.sql`。必须看到：
   - `catalog_rows` 至少包含本来源的 50 行，`reviewed_source_rows=50`；
   - `image_rows=28`（如果表中没有别的来源数据），`names_with_images=26`；
   - `prefix_rules=2`，本来源每行按 Word 顺序列出；
   - `invalid_images=0`；
   - 缺图附件的 `image_count=0`。
6. 如果 Render API 使用的数据库角色不是执行建表的角色，只给实际 API 角色授予这两张表的 `SELECT` 权限。不要授予客户端写权限。
7. 部署包含 `api/attachment_image_query.mjs`、`api/attachment_service.mjs` 和更新后 `Dockerfile` 的 API 版本。当前改动尚未提交或部署，需按现有人工 Git/Render 流程执行。
8. API 部署后，用本机现有客户端配置只读取目录并检查计数。以下命令不会打印密钥：

   ```powershell
   $cfg = Get-Content -LiteralPath 'G:\gongsi\banjinxitong\板件后续二次修改\AIQuoteDualSystem\client_config.json' -Raw -Encoding UTF8 | ConvertFrom-Json
   $apiBase = ($cfg.api_url -split '/api/')[0].TrimEnd('/')
   $body = Invoke-RestMethod -Method Get -Uri "$apiBase/api/attachments/catalog?v=2" -Headers @{ 'X-AI-Quote-Key' = $cfg.api_key }
   [pscustomobject]@{
     image_catalog_rows = @($body.attachment_images).Count
     image_rows = (@($body.attachment_images) | ForEach-Object { @($_.images).Count } | Measure-Object -Sum).Sum
   }
   ```

   预期 `image_catalog_rows=50`、`image_rows=28`。不要输出 `$cfg`、请求头或 API 密钥。
9. 打开新版客户端，进入附件选择并选择一个有图附件，再回到报价计算页。附件表格“图片”列应显示数据库图片；选择“绑线条”等缺图附件时该列为空。分别检查“风机”和“过滤网”的不同型号都能显示共用图片。

## 回退

API 代码可回退到部署前版本；新表不会参与报价，保留也不会改变报价结果。如需撤销本次图片数据，在确认来源 SHA-256 后用一个事务删除该来源的资源和目录行。不要删除附件价格、历史选择或报价表。优先使用执行前创建的 Neon 恢复分支处理误操作。
