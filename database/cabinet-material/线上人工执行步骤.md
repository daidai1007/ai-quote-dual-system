# 完整柜体材料重量目录上线人工步骤

本目录只提供人工执行材料。本地工作未连接或修改线上数据库，也未部署 Render API 或客户端。统一上线时优先使用 `database/online-rollout-20260911/线上数据库完整人工步骤.md`。

## 数据依据

- 面积公式：`JS,JP,JA,JE,JK,JM材料明细-面积公式.xlsx`，SHA-256 `91cc0a5f841b74559a34a7408a604e41d5fe76e8db3743b20a32ff657c2b2151`。
- 经验重量：`JC,JQ,JP超宽，JS超宽，操作台重量表.xlsx`，SHA-256 `e6f7110cb06267ca9d26ca3f7a7bbc23bbb5beb6a26f0545970ef8ca8beb1e99`。
- 合并版本：`cabinet-material-4f8bf726efa6568d-v2`，合并 SHA-256 `4f8bf726efa6568df4ea540f162598f49b09f0174f61c3578ac5189721f17a7f`。
- 普通柜面积规则 241 条；经验重量 46 条。
- 普通柜损耗系数默认 1.2，程序传值优先。经验重量不乘损耗系数。

## 执行顺序

1. 在 Neon `production / Primary / neondb` 完整运行 `web/00-preflight.sql`。
2. 完整运行 `web/01-create.sql`。该文件安装 V2 表、导入/激活函数及兼容重量函数，不激活版本，也不删除旧数据。
3. 完整运行 `web/02-stage.sql`。返回值必须是 `cabinet-material-4f8bf726efa6568d-v2`。
4. 完整运行 `web/03-validate.sql`。必须得到 241 条面积规则、6 个普通产品族、46 条经验重量、5 个经验产品代码，`any_waste_factor` 全部为 `false`，重复身份查询返回 0 行。
5. 由你提交 GitHub，并部署健康标识为 `2026-09-11-complete-cost-catalogs-v5` / `20260911-complete-cost-catalogs-v5` 的 Render API。
6. 统一上线时运行 `database/online-rollout-20260911/01-activate-current-catalogs.sql`，不要单独运行 `web/04-activate.sql`。只有单独恢复材料目录时才使用 `web/04-activate.sql`。
7. 分别验证普通柜、JC 豪华/标配、JQ、JP/JS 超宽柜和操作台。普通柜把损耗系数从 1.2 改为 1.3 时计价重量应变化；经验产品把损耗系数从 1.2 改为 1.8 时重量和材料成本必须不变。
8. 完整运行 `web/05-verify.sql`。示例重量应包含 JQ SECC `54.000000`、操作台 SUS316 `77.300000`、JC 豪华型 `90.300000`。
9. 完成保存、重开和导出验收后，统一运行退役目录清理脚本。该清理只删除替换目录中的 `RETIRED` 版本，不删除报价快照。

经验产品的标准尺寸精确命中；非标准尺寸沿用现有 `(宽+高+深)` 比例。JQ 和操作台优先使用源表明确的 SECC 或 SUS304/SUS316 重量。JC 与 JP/JS 超宽柜源表只提供 SECC；选择不锈钢时按 `calc.material` 当前密度换算。两种情况都不乘损耗系数。

`calc.experience_product_model` 还可能被快速报价或其他兼容路径使用，本次不直接删除整表。并柜运行规则不修改。
