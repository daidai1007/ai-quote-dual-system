# Excel 台账生成合同：新增迁移与配套接入

本目录仅提供迁移与核对脚本。本任务只在独立、一次性的本地 PostgreSQL 中执行过，不代表线上已部署。

## 上线顺序（由总修改统一执行）

1. 合并本任务补丁，保留其他任务当前修改。确认已有 `contract_templates_v1.sql` 合同模板表、不可修改触发器、合同编号序列；客户资料迁移仍遵循现有项目方案。
2. 在目标环境执行只读 `contract_ledger_v1.preflight.sql`，按既有流程备份并核对数据库身份。
3. 执行 `contract_ledger_v1.sql`，再执行只读 `contract_ledger_v1.verify.sql`。如数据库迁移账户与 API 账户不同，按现有权限管理方式授予 API 对新增草稿表的 SELECT/INSERT/UPDATE、生成记录表的 SELECT/INSERT；保留既有模板、审计表和序列权限。脚本不写入角色名或密钥。
4. 更新配套 API（`contract_service.mjs`、`contract_ledger_data.mjs`、`contract_ledger_service.mjs` 和 `server.mjs`）。旧客户端与旧报价合同接口继续可用。
5. 发布人员在构建环境安装客户端 `requirements.txt` 中的 `xlrd==2.0.2`，按原流程处理客户端构建和发布；本任务没有执行构建。
6. 用户在“合同管理 → 生成合同 → 从 Excel 台账生成”选择两家客户，上传各自模板或使用现有共享模板，确认字段配置含名称、规格、数量、单位、单价、金额和备注。现有提供的两个空白 XLSX 模板可自动识别占位符。未配置模板保留原手工配置入口。

## 数据与权限

- 新增 `calc.ledger_contract_draft`、`calc.ledger_contract_generation`，不放宽原 `contract_generation` 的正式报价外键、外部性质和版本要求。不会创建假报价，台账合同不计入报价分析。
- 新接口均要求原姓名会话。模板按现有规则共享使用，维护限上传人；台账草稿限本人。合同元信息沿用原本人/全部范围，原文件、打印、导出仍限生成人。
- 原报价合同入口继续拦截内部报价、未分类报价及无操作权报价。台账接口不接受 `scheme_no`、`order_nature`、`owner` 等字段，不能借新流程引用内部报价。
- 台账只读解析；只上传选中的来源行及独立备注修改，不上传整本台账，不写回 Excel。草稿保存所选行，生成后冻结模板版本、原备注、人工备注、金额和实际 Office 文件；重新打开不依赖原台账或当前价格。
- 两个新增表之外的业务数据不迁移、不回填；迁移可重复执行。所有生成文件受不可修改触发器保护。

## 功能规则与限制

- 诺玥：D 列“钉钉合同号”相同的全部记录合成一份，名称直接取 E 列；多个合同号分别生成。
- 方圆：所选物理行合成一份，本次合同编号由用户填写，不采用第一条旧编号；签约日期单独确认。
- 备注取产品明细旁 N 列，保留原文并允许单独修改/清空/恢复；不读取后面的发货备注替代。
- A 列重复序号不去重，来源定位为文件 SHA256＋工作表＋原始行。合同内产品序号重新连续编号。
- 台账限 XLS/XLSX 64MB；单份合同最多 500 行，一批最多 20 份，输出单文件最多 16MB、全批最多 64MB。数量单价与小计不符、缺失数值和公式缓存错误均阻止生成，禁止补零或静默重算价格。
- Office 预览与打印复用原 LibreOffice/Poppler 组件；缺少组件时保留已生成记录及原文件导出，并显示原有说明。

## 回退

先回退客户端入口与 API 到匹配版本即可停用新功能。保留新增两张表和已生成文件，旧报价合同仍可运行。不要通过删除表或关闭不可修改触发器回退；已生成数据有留存价值。需要恢复新功能时重新部署匹配 API/客户端。

## 本地复测

仅使用合成记录和一次性本地数据库：`npm run test:contract-ledger`；客户端测试环境安装 `tests/requirements-contract-ledger.txt` 后执行 `npm run test:contract-ledger:client`。客户实际台账核查只记录结构、计数和校验值，不纳入测试夹具或补丁。
