## 关于“删除旧表”的准确边界

本次可以物理删除的是旧目录数据和已经退役的替换目录。以下现役核心表不能删除：

| 对象 | 当前用途 | 处理 |
|---|---|---|
| `calc.attachment_price` | 新版附件目录和历史外键目标 | 保留表；删除未引用旧行 |
| `calc.attachment_classification` | 新版附件分类 | 保留表；随未引用旧价格行清理 |
| `calc.attachment_selection` | 历史及新版附件选择快照 | 全部保留 |
| `calc.attachment_catalog_version` 及成本规则表 | 新版附件版本和公式规则 | 保留活动版本；删除无历史引用的退役版本 |
| `calc.cabinet_material_catalog_version`、`calc.cabinet_material_rule`、`calc.cabinet_material_fixed_rule` | 普通柜公式重量、经验重量和材料成本 | 保留活动版本；删除退役版本 |
| `calc.cabinet_spray_catalog_version`、`calc.cabinet_spray_rule`、`calc.cabinet_spray_fixed_rule` | 新柜体喷塑面积、经验价格和成本 | 保留活动版本；删除退役版本 |
| `calc.cabinet_auxiliary_catalog_version`、配置、明细及固定价格表 | 完整柜体辅材目录 | 保留活动版本；删除退役版本 |
| `calc.cabinet_labor_catalog_version`、`calc.cabinet_labor_rule` | 新柜体人工规则 | 保留活动版本；删除退役版本 |
| `calc.cabinet_part_rule` | 当前只剩公式模板接口仍依赖 | 暂时保留，完成模板接口和客户端预览迁移后另行删除 |

两份完整材料源文件已经合并到材料 V2；两份完整辅材源文件已经合并到辅材 V2；两份完整喷塑源文件已经合并到喷塑 V2。激活全部目标目录并部署 `complete-cost-catalogs-v5` API 后，可分别按 `database/online-rollout-20260911/auxiliary-cleanup/README.md` 和 `database/online-rollout-20260911/spray-cleanup/README.md` 清理旧辅材及旧经验喷塑表。`experience_product_model` 和旧 `labor_experience_rule` 可能仍有快速报价或兼容函数依赖，在依赖审计完成前不整表删除。

不要执行 `DROP TABLE calc.attachment_price`、`DROP TABLE calc.attachment_selection`、`DROP TABLE calc.attachment_classification` 或 `DROP TABLE calc.cabinet_part_rule`。也不要执行 `TRUNCATE ... CASCADE`。这些操作不是“清除旧目录”，而是删除现役结构或报价历史，会使当前 API、客户端或历史报价失效。

如果预检输出出现其他名称明确为旧备份/临时表的对象，先用外键清单和 `pg_depend` 证明没有 API、视图、函数或历史表依赖，再针对明确表名单独写 `DROP TABLE`。当前线上证据没有确认任何这样的独立旧表名，所以本交付不猜测名称并批量删除。

- 不要重复执行附件 `web/02-stage.sql`；线上 r4 已经激活并完成清理。
