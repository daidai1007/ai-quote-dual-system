# 快速报价只按尺寸选择面价：线上数据库人工步骤

需要修改数据库，因为最终面价由 `calc.match_quick_quote` 选择。本次只替换匹配函数，不更新、删除或插入任何面价数据。

修改后的规则：

- 单门/双门数量不参与快速面价选择；单双门产品代码归一到同一快速报价目录。
- 型号文字不参与候选排序。
- 产品、材质、有效日期、宽度、高度和深度继续参与匹配。
- 候选柜体先按宽度差从小到大匹配；宽度一致后，再按柜体周长差从小到大匹配；仍相同时用三维距离和现有稳定排序决胜。
- 非标尺寸保留现有周长比例换算，仅改变参考柜体的选择顺序。
- 门型仍参与公式法材料、喷塑和辅材计算。

## Neon SQL Editor 操作

1. 选择 production / Primary / `neondb`。若页面显示 `In transaction`，先执行 `ROLLBACK;`。
2. 完整执行 `00-readonly-preflight.sql`。`function_exists` 必须为 `true`；记下 `active_quick_rows`，更新后数量应保持不变。
3. 完整执行 `../migrations/enforce_quick_quote_dimension_only.sql`。不要只运行选中的部分语句；必须看到整个事务成功提交。
4. 完整执行 `02-readonly-verify.sql`。七项检查必须全部为 `true`，并且 `result=PASS`；`active_quick_rows` 必须与预检记录相同。
5. 打开公开的 `/health`，确认 `ok=true`。`/api/health/database` 受现有客户端密钥保护，应使用已有的授权诊断方式请求，确认 `ready=true` 且全部 `checks` 为 `true`；不要在聊天、截图或日志中显示密钥。
6. 在客户端选择同一个产品、材质和尺寸，依次切换 `1/0`、`0/1`、`2/0`、`1/1`、`0/2`。五种门型的快速报价面价必须完全相同；公式法成本允许随门型变化。

如第 4—6 步失败，完整执行同目录的 `03-rollback-width-priority.sql`，精确恢复上一版“周长优先、忽略门型和型号文字”的匹配函数，然后重新运行只读预检查。
