# 当前管理费规则

管理费＝（材料成本＋辅材成本＋柜体人工成本＋当前附件弹窗已确认成本＋喷涂费用＋运费）×0.06。

- 普通柜按单台，并柜按整套计算；再乘订单数量。人工倍率只作用于柜体人工。
- 各成本先按金额精度汇总，管理费四舍五入至分；运费参与基数，但不重复计入基础 `total_cost`，界面最终成本再加一次运费。
- 不读取旧管理费、旧管理费率，也不从旧总价倒推成本基数。原始管理费/总价为空不影响计算；真正缺少柜体成本分项时须重新报价，不补零。
- 附件人工售价、人工成本、数量、加减项仍以已确认弹窗行快照为准；不重新查询附件目录或改写旧报价快照。
- 快速报价面价仍按现有经验价格规则计算，不额外加收管理费。

## 部署

1. 在 Neon 的当前业务数据库执行 `migrations/enforce_management_fee_6_percent.sql`。脚本更新两个基础成本函数、人工目录导入校验及当前/待启用目录费率元数据，可重复执行，不删除表、不改写历史报价。
2. 重新部署当前 API，并构建客户端。只替换客户端不足以修复线上生成报价时的旧快照校验。
3. 对现有 JE 740×500×900 报价再次生成报价单，核对管理费 124.32、含运费成本 2,196.37，确认附件人工修改仍保留。

数据库基础函数没有运费输入，先按运费为零计算。API、客户端和导出在获得实际运费及确认附件后，均重新按上述完整六项公式计算，并非沿用数据库的中间管理费。

本次代码变更不会自动执行线上迁移、部署 API 或覆盖客户端。
