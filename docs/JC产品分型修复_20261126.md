# JC 标配型与豪华型

选型配置中的 JC 拆成“JC 标配型”和“JC 豪华型”，实际业务产品仍是 JC_EXP。两项分别发送 STANDARD、LUXURY 配置，成本及快速报价独立取价。

用户确认的面价型号：

| 配置 | 面价型号 |
| --- | --- |
| 标配型 | JC601660-1、JC601680-1 |
| 豪华型 | JC601660-2、JC601680-2 |

## 计算与历史兼容

成本以显式配置选取现有材料、喷涂、辅材、人工规则，不把面价型号后缀直接当成旧成本规则的后缀。显式配置优先于门数量和型号推断。仅供旧内部直接调用的成本后缀兼容保留；正常报价 API 会先统一为显式配置。

面价先筛选同型有效记录，再按宽度、周长、表面积及原有后续优先级匹配。非标尺寸沿用原周长比例。型号后缀优先于旧表名中的类型文字。同型面价缺失、失效，或者分型成本目录不完整时返回可读错误，不能跨型借价。

手工重新匹配面价沿用原报价配置，并柜每个子柜保留同一配置。型号建议也分别过滤。保存的产品名称包含类型，重开、刷新目录后保持类型。旧 JC 行没有类型但带上述面价型号时可恢复类型；完全无法判断时要求操作员选择。读取历史行不重算、不改写其金额。

## API 人工更新

本轮不涉及数据库迁移，也不构建或覆盖客户端。API 由管理员手工部署已审核的 Git 提交。

1. 备份当前 API 部署版本，记录 Git 提交号和环境变量配置；不要将密钥写入仓库。
2. 审核并上传本轮 API 文件：新增 `api/jc_profile.mjs`、`api/jc_quick_match.mjs`，更新 `api/server.mjs`、`api/door_variant_rules.mjs`、`api/quick_match_override.mjs`，及四个 `api/cabinet_{material,spray,auxiliary,labor}_service.mjs`。新模块必须一并上传，不能只覆盖 server。Docker 部署还必须包含本轮 `Dockerfile` 和 `.dockerignore`：两个新模块既要加入 COPY，也要放行构建上下文；只在仓库中存在文件不能保证镜像包含它们。提交部署前运行 `npm run test:api-image` 核对两个启动入口的静态依赖完整性。
3. 在现有 Render/GitHub 部署流程中手工部署审核后的版本。现有数据库表、校验函数及 SQL 函数不用替换。本轮没有数据库迁移或回填脚本。
4. 管理员只读核对现有面价目录是否包含两型有效记录，以及四项成本目录的 STANDARD/LUXURY 数据是否齐全。离线夹具测试不能证明正式目录已经齐全。面价核对可使用下面的 SELECT，勿改价。
5. API 就绪后，后续另行获准构建的客户端才能使用两型选择。新客户端必须配套本次 API；旧 API 的门型归一化不能保证 JC 分型取价。当前现场安装包尚未包含本轮客户端源码修改。
6. 在合成或专用验收数据上逐个验证四个型号、切换类型、保存重开、手动匹配及 Excel 导出；正式历史报价不要批量重算。若需回退，恢复备份的 API 与客户端版本；数据库无需操作。

若镜像构建成功但启动时出现 `ERR_MODULE_NOT_FOUND`，先核对运行日志中的缺失文件和当前提交是否已包含上述 Docker 修复。`377c756` 的文件清单遗漏了两个 JC 模块，应部署包含后续打包修复的提交；不需要为此修改数据库、密钥或清理客户端。

采用当前仓库的 Render 流程时，先由管理员审核并提交、推送本轮文件，再在 `ai-quote-dual-test` 选择 **Manual Deploy → Deploy latest commit**，核对部署的提交号及 `Live` 状态。操作入口可参照 [Render 官方部署说明](https://render.com/docs/deploys#manual-deploys)。部署失败时检查运行日志，不执行数据库补丁。本文不授权自动提交、推送或部署，也不表示现场目录已核对通过。

```sql
SELECT quick_rule_id, model_code, material_code,
       reference_width_mm, reference_height_mm, reference_depth_mm,
       quick_base_price, quick_total_cost, source_sheet,
       effective_from, effective_to, is_active
FROM calc.quick_quote_experience
WHERE product_code = 'JC_EXP'
  AND model_code IN ('JC601660-1','JC601680-1','JC601660-2','JC601680-2')
ORDER BY model_code, material_code, effective_from;
```

上面的查询列出有效期和启用状态，仍需按实际报价日期、材质检查。四项成本使用 `profile_code`，不能用面价型号的 `-1/-2` 后缀判断旧成本记录的类型。下面的只读查询列出当前 ACTIVE 版本的分型规则及覆盖尺寸、材质；缺行或缺少所需组合时先记录问题，不在本轮补录或改价。

```sql
SELECT '材料' AS cost_kind, r.profile_code, r.model_code,
       r.width_mm, r.height_mm, r.depth_mm, r.material_codes, r.data_version
FROM calc.cabinet_material_fixed_rule r
JOIN calc.cabinet_material_catalog_version v USING (data_version)
WHERE v.status = 'ACTIVE' AND r.product_code = 'JC_EXP'
UNION ALL
SELECT '喷涂', r.profile_code, r.model_code,
       r.width_mm, r.height_mm, r.depth_mm, r.material_codes, r.data_version
FROM calc.cabinet_spray_fixed_rule r
JOIN calc.cabinet_spray_catalog_version v USING (data_version)
WHERE v.status = 'ACTIVE' AND r.product_code = 'JC_EXP'
UNION ALL
SELECT '辅材', r.profile_code, r.model_code,
       r.width_mm, r.height_mm, r.depth_mm, r.material_codes, r.data_version
FROM calc.cabinet_auxiliary_fixed_rule r
JOIN calc.cabinet_auxiliary_catalog_version v USING (data_version)
WHERE v.status = 'ACTIVE' AND r.product_code = 'JC_EXP'
UNION ALL
SELECT '人工', r.profile_code, r.model_code,
       r.width_mm, r.height_mm, r.depth_mm, r.material_codes, r.data_version
FROM calc.cabinet_labor_rule r
JOIN calc.cabinet_labor_catalog_version v USING (data_version)
WHERE v.status = 'ACTIVE' AND r.product_code = 'JC_EXP' AND r.rule_kind = 'FIXED'
ORDER BY cost_kind, profile_code, model_code, width_mm, height_mm, depth_mm;
```

验收时分别核对 STANDARD、LUXURY 在四项成本中都有适用规则；600×600×1600、600×800×1600 及实际使用的材质应有对应记录或既有允许缩放/密度转换的规则。仅有记录数量不能证明全部组合可报价。若查询提示表不存在或版本不唯一，暂停更新，保留错误交总修改核对；不要创建表或启用目录。

## 本地复跑

客户端使用项目既有 Python 3.12 / PySide6 环境和 V3 core，设置 `QT_QPA_PLATFORM=offscreen`、`AI_QUOTE_V3_CORE_ROOT`，运行 `tests/verify_jc_profiles.py` 和 `tests/verify_jc_roundtrip.py`。前者拦截外部 socket，真实构造 Qt 窗口和报价请求；后者经真实 Qt 保存控制器、内存服务应答、JSON 序列化、重开和实际 Node Excel 导出检查四个型号的类型与金额，未保存到正式服务。

API 专项包括 `tests/jc_profiles.test.mjs`、`tests/jc_server_flow.test.mjs`、`tests/jc_quick_match_sql.test.mjs`。服务流程测试使用 `node --experimental-vm-modules --test`，仅替换 HTTP 监听与 psql 边界，执行实际服务函数。SQL 测试的 `AI_QUOTE_PGLITE_MODULE` 指向隔离安装的 PGlite 模块；只新建纯内存夹具，不连接现有数据库。PGlite 不是生产依赖，不需要修改 package.json 或安装到 API。

测试证据位于工作区的 `测试报告_JC分型_20261126`，包括真实 Qt 截图、合成 Excel、各组日志及验证清单。
