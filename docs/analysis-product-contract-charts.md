# 报价分析：产品分类与合同/已报价趋势

2026-10-29 用户确认采用方案一：保留现有趋势、客户 Top 5、成本结构，在其下增加宽幅产品分类图；趋势改为“合同与已报价趋势”。本说明及源码交付不执行数据库更新、API 部署或客户端构建发布。

## 统计与交互

- 分类图只读正式报价的冻结行金额和数量，不读取当前目录价、不重新计算报价。
- 同类产品归并多个内部代码；JP WIDE、JS WIDE独立于JP、JS。分类沿用选型的产品族规则。无法识别的历史项显示“产品待分类”，不猜测类型。
- 多产品方案的每个分类只计算该类自己的行金额。同一方案同类多行合并到该类一条明细，跨分类不重复加入整单金额。
- 默认显示金额，切换台数后重新排序、显示数量占比。条目点击、空格或回车打开沿用现有样式的明细窗口，可双击打开来源方案。
- 金额按分汇总；数量按冻结数量汇总。缺失值显示“—”，并列出覆盖/缺失行数；真实的0仍为0。旧成本统计使用的默认数量1保留在原字段中，新图的原始数量单独读取，避免把旧成本默认乘数当成报价台数。
- 原筛选、成本、折扣、成交登记、报价总额及原有图表规则保留。分类图采用与现有正式报价集合相同的筛选范围；合同趋势按其各自事件日期筛选。
- 合同趋势按实际新生成合同逐份统计，来源为此前已授权的合同登记关联；同一方案生成多份新合同分别计数，幂等重试不会新增关联。
- 已报价趋势按现有正式报价方案和正式报价日期统计。新建草稿日期不参与这张新趋势图。原 API 的 `trend`/`trend_details` 字段保留兼容，客户端改读新的趋势字段。
- 合同使用合同生成记录的日期（上海时区）；即使来源方案已进入新修订，也能看到已登记的旧正式版本合同，明细可打开对应实际合同。
- 合同记录遵循本人/全部报价权限，筛选状态沿用来源方案当前状态，作废方案不纳入趋势。合同不自动计为成交。
- 台账合同在全部产品范围参与合同趋势；没有产品族编码的台账不虚构分类，也不伪造正式报价金额/台数。
- 趋势数值单位为份。合同 KPI 仍是“当前状态为合同的方案数”，趋势中的合同数是实际合同份数，两者不要求相等。
- 失败或切换筛选时清空旧图表；旧 API 缺少新字段时提示更新，不能把旧“新建方案数”画成合同数。
