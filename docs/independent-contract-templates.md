# 客户模板独立维护

客户模板可在该客户还没有正式报价时提前上传、配置字段及保存版本。

## 操作

1. 打开“合同管理 → 客户模板”，点击“上传客户模板”。
2. 选择不超过 8 MB 的 DOCX 或 XLSX 文件。
3. 选择已有客户名称，或输入客户公司全称，填写模板名称并上传。
4. 在模板列表选中该模板，点击“配置字段”，核对填入位置并保存。
5. 后续更新文件用“上传新版本”；修改字段配置也会产生新版本。

本步骤不要求先创建报价，不生成占位报价或合同，不新增客户资料表记录。
模板维护人仍为实际登录姓名。模板可供同事使用，只有维护人可修改。
正式合同生成继续需要本人有权使用的正式外部报价，或现有台账合同来源。

没有报价时，模板也能重新加载、查看配置和版本记录。后续该客户出现正式
报价后，模板按客户身份匹配；提前维护时还没有客户档案、以后才建立档案的
场景也支持。同客户同模板名应使用“上传新版本”，不能重复新增。

## API

沿用 `POST /api/contracts/templates`，姓名会话及共享连接认证规则不变。
独立新增上传请求不需要 `scheme_no`、`version_no`：

```json
{
  "customer_name": "某客户有限公司",
  "template_name": "标准采购合同",
  "filename": "contract.docx",
  "format": "docx",
  "content": "文件的Base64内容"
}
```

独立上传新版本时传 `group_id` 和 `expected_version`。所属客户取原模板记录，
不能在上传新版本时换客户。仍支持旧客户端携带正式报价的原上传协议。
字段配置沿用 `POST /api/contracts/templates/{id}/configure`，并保存新的不可变版本。

客户代码由服务端确定：已有唯一客户档案时取该代码，否则使用公司全称生成
现有的名称键。客户端不能伪造代码指向其他客户。后续档案建立不会令名称键
模板失配，也不会为该公司生成同名重复模板。名称键仅供内部匹配，不在界面显示。

## 部署与边界

- 更新 API：`api/contract_service.mjs`、`api/contract_template_policy.mjs`。
- 更新客户端源码：`desktop_client/contract_management.py`。
- 无新数据库结构、迁移或目录更新 SQL。使用已有模板分组、不可变版本及审计表。
- API 与客户端须配套更新。只更新 API 不会让现用旧 EXE 出现独立上传入口。
- 此项修复没有向业务环境上传模板、更新数据库或构建发布客户端。
- 原有 12 份本地待上传模板不会因代码合并自动进入业务模板库；应在配套更新后正常上传和配置。
- 此功能不扩展现有台账导入支持的客户格式。

## 验证

`npm run test:contract-templates-independent` 使用自有一次性本机 PostgreSQL，
验证无报价上传/配置、版本不可变性、权限、重试冲突，以及以后新增正式报价
和客户档案时的模板匹配。

`tests/verify_contract_template_independent.py` 使用真实 Qt、临时 HTTP API 和合成
合同文件验证操作入口、独立上传配置、重新加载及新版本维护。
相关合同生命周期、共享权限和界面回归继续保留。
