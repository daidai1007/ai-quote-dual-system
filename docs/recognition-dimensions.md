# 尺寸识别与回填约定

本次改动以 `173671a686b41dd2635702d4b8129407551396c6` 为基线，借鉴测试结果17的证据分层，适配现有 V3 核心及方案二。保留现有识图模型、服务、报价 API、数据库和导航。

## 轴与底座

- 内部 `dimensions` 为 `(宽 W, 本体高 H, 深 D)`；显示规格为 `W*D*H`。不能直接连接内部 tuple 生成显示规格。
- `800*600*(1800+100)` 的计价本体高是 `1800`，底座是 `100`，总高是 `1900`。
- 复用核心 `parse_review_specification` 时只提取规格、轴与高度分段，不能继承其“人工复核”来源或 `1.0` 置信度。
- 方案二人工分段宽输入沿用 `ganged_cabinet_rules`：完整规格保留分段表达式，隐藏的旧控件及旧核心保存兼容层使用首柜尺寸；并柜各子柜仍由原报价流程计算。

## 证据处理

`recognition_dimensions.py` 是不依赖 Qt、OCR 或网络的纯规则模块。完整规格、旧 WHD tuple、PDF 原生具名轴分别保存来源；不一致时保留候选并转为待核对。

修正层仅在单页 PDF、至多一个柜体且没有实际区域坐标时，读取原生文字中的明确宽/深/高标签或明确顺序标题。支持明确的 mm/cm/m 单位换算、本体高+底座和总高减底座；不猜测无轴标签三元组的顺序，不截取加法、范围或未知单位的数字前缀。

原生文字补充是独立证据路径。原有 OCR 冲突、底座冲突、人工交叉核对要求和只供复核的标记仍受门禁约束。单份 OCR 文字即使能提取三个具名轴，也只能提供核对线索，不自动绕过原有核验要求。

几何部分尺寸只保留唯一宽/深候选，不从多个数字取最大值，不补造高度。多个柜体时禁止把整页几何轴复制到各候选。`source_region` 的空位置占位字典不被误判为真实区域。

记录新增的 `dimension_recognition` 保存状态、候选来源、部分轴和冲突；`dimension_review_required` 表示当前尺寸是否仍待核对。原 OCR 共识保留用于追溯，人工修改记录为 `manual_quote_fields`。

## 用户流程

完整可信尺寸正常回填。缺失、冲突或尚未完成交叉核对时，清除上一张图的可见规格和报价缓存，用现有输入框显示部分轴占位及“待核对”；悬停可看候选。

三个入口——加入报价动作、直接计算、直接加入清单——均在使用旧尺寸或读取附件价格前检查待核对状态。用户对照原图输入有效规格后，按当前 parser 同步隐藏轴和来源记录，再继续原计算流程。保留人工尺寸时同时保留显示字符串和三个数值轴。

本轮没有恢复旧识图工作台，没有增加 API/数据库门禁。客户端元数据和门禁不是服务器端原图验真；历史报价/外部客户端仍按原协议处理。

## 验证

新增 `tests/verify_recognition_dimensions.py` 使用合成数据及 PDF，不调用 OCR；`tests/verify_recognition_dimensions_ui.py` 使用当前实际 V3 核心的解析器和 Qt 控件，禁止网络，并禁用更新检查、目录加载及真实识图。覆盖轴顺序、底座、缺失/冲突、原有门禁、多柜/多页作用域、人工修改、并柜兼容和缓存阻断。

两个新测试已加入 `tests/run_client_tests.ps1`；原有 direct-recognition 测试的错误 WHD 显示断言已改为 WDH。测试环境需 Python 3.12 x64、PySide6、pypdf 及 `AI_QUOTE_V3_CORE_ROOT` 指向已验证核心。本次未构建客户端、未调用真实识图服务，真实图纸识别准确率和安装版效果仍需人工验收。
