首次安装包安全检查与发布规则

1. 使用 build_first_install.py，从已验签的程序专用更新 ZIP 生成首次安装包。
   不复制开发电脑的整个客户端目录。仅保留 Render API 地址，api_key 留空；
   仅复制五个允许公开的更新配置字段，不包含更新签名私钥或用户业务文件。

2. 构建目录必须位于 HTTP 下载根目录之外。
   完整解包目录、最终安装 EXE 均须通过真实 Microsoft Defender 检查。
   每个对象先做包含档案、忽略排除项的取证扫描，再做普通自定义扫描。
   检测到威胁、扫描失败、实时保护未开启或防护/排除设置发生改变，均停止发布。
   未通过门禁的构建产物只能保留作分析，不能发送给使用人员。

3. 不关闭实时保护，不创建排除项，不恢复已隔离样本，不更改云保护或样本提交策略。
   不通过改名、改后缀、加密压缩或反复变化安装器结构规避检测。
   不主动向第三方上传安装包或源代码；需要厂商复核时先获得用户授权。

4. scan-result.json 记录防护状态、病毒库版本、两种扫描结果和检查边界。
   任何“未检出”结论仅适用于所记录的文件、哈希和检测版本，不能保证绝对安全，
   也不等同于微软正式给出误报裁定。

5. 仅向使用人员发送已通过复核的安装 EXE、安装说明、安全说明和 SHA256SUMS.txt。
   接收电脑先更新 Defender 安全情报，核对文件哈希并自行扫描后再安装。
   接收电脑仍报毒或受公司策略阻止时停止安装，保留检测名称和文件哈希交管理员处理。
   Windows 未知发布者/SmartScreen 下载信誉提示与明确的恶意软件检测是不同问题。

6. 首次安装包仍需单独配置合法业务 API 密钥；API 位于线上 Render，
   内网 HTTP 服务仅用于程序更新。这两个服务不得混淆。
